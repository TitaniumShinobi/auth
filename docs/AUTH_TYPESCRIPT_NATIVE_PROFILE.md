# TypeScript/Node/Express/Prisma native profile

Profile `typescript-node-express-prisma/2` is the first public target-native profile. Its authoritative source is `profiles/typescript-node-express-prisma/`; the wizard maps that directory into ordinary product-owned `src/` and `prisma/` paths. It no longer copies the repository's historical LIFE/VVAULT/Chatty application.

The profile provides product-neutral credentials, magic-email delivery, secure cookie sessions, OAuth authorization-code with S256 PKCE, access tokens, refresh rotation and replay-family revocation, logout/revocation, Prisma persistence, OAuth metadata, and an OAuth-protected MCP resource boundary. Clients and upstream providers are configuration data. The MCP transport and tool implementation remain product-owned; the profile authenticates the request and exposes the bound subject/scope rather than creating another identity authority.

Required configuration is `AUTH_ISSUER`, a high-entropy `AUTH_SIGNING_SECRET`, `DATABASE_URL`, and `AUTH_CLIENTS_JSON`. Magic email additionally requires `AUTH_MAGIC_DELIVERY_URL` and `AUTH_MAGIC_DELIVERY_TOKEN`. `AUTH_PROVIDERS_JSON` optionally declares issuer, authorization, token, userinfo, JWKS, client, and scope configuration. Provider callbacks consume state once, verify issuer/audience/nonce for ID tokens, require a verified email, and reuse the provider subject or normalized email instead of creating duplicate identities. Secrets are runtime inputs and never appear in a plan, receipt, generated source, or standards contract.

The generated server listens on loopback by default and exposes `/health`, `/ready`, `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/magic/request`, `/api/auth/magic/verify`, `/api/me`, `/oauth/authorize`, `/oauth/token`, `/oauth/revoke`, authorization-server metadata, protected-resource metadata, and a fail-closed `/mcp` boundary. Products own external routing, TLS termination, visible UI, delivery infrastructure, provider registration, deployment, monitoring, and MCP tools.

The product-owned `test/profile.test.mjs` starts the built runtime and isolated delivery/provider fixtures on ephemeral loopback ports. It verifies readiness, metadata, hardened cookies, credentials, `/api/me`, S256 authorization code exchange, resource-server audience tokens, authenticated and unauthenticated MCP boundaries, refresh rotation, replay-family revocation, logout, magic-link single use, OIDC issuer/audience/nonce and callback-state handling, and provider identity reuse. It uses an isolated temporary database and stops every process and server it starts. Live provider registration and delivery credentials remain external acceptance actions.

The bundled Prisma schema and initial migration use SQLite for deterministic local installation and acceptance. Run the locked install, `npm run prisma:generate`, `npm run prisma:migrate`, and `npm run build` before startup. The migration script creates the configured SQLite file with owner-only permissions when absent because Prisma deploy does not create it; non-SQLite URLs are left untouched. A product needing PostgreSQL or another provider requires an explicit reviewed profile migration; AUTH does not rewrite a live datasource or schema implicitly.
