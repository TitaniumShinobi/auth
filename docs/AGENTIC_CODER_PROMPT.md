# AUTH agent integration prompt

Run AUTH's transient native workflow for this product. Start with read-only `native discover` and `native assess`. For greenfield work, generate and review a `native plan`; for existing authentication, use `native align-plan`. Apply only the exact authorized plan and finish with fresh runtime observations and read-only VERIFY.

AUTH owns the reusable authentication profile and standards. Do not create an AUTH adapter, daemon, shadow service, `.auth-runtime`, `.auth-kit`, copied package, lifecycle control plane, or source-checkout dependency. Do not manually recreate provider, session, refresh, identity, or persistence architecture.

When AUTH returns `AGENT_INTEGRATION_REQUIRED`, change only the named product-owned UI, routing, configuration, deployment, observation, delivery, or MCP transport/tool seam and produce the expected evidence. `AUTO_REPAIR_AVAILABLE` uses a registered bounded handler. `EXTERNAL_ACTION_REQUIRED` waits for credentials, provider registration, legal choice, or irreversible migration authority. `AUTH_DEVELOPMENT_REQUIRED` returns missing reusable behavior to AUTH.

Preserve product files, secrets, identities, sessions, and data. Never print secrets. VERIFY and assessment are read-only; REPAIR never changes versions; MIGRATE is explicit and lineage/rollback aware.
